# Деплой на бесплатный хостинг: Render + Supabase

Занимает около 15 минут, карта не нужна.

| Что | Где | Почему |
|---|---|---|
| Приложение | [Render](https://render.com), бесплатный веб-сервис | Собирает образ прямо из `Dockerfile` |
| База | [Supabase](https://supabase.com), бесплатный Postgres | У Render диск стирается при перезапуске, а его бесплатный Postgres удаляется через 30 дней |

## 1. База в Supabase

1. Зарегистрируйтесь на supabase.com и создайте проект. Пароль базы сохраните. Регион — ближайший к региону Render (например, Frankfurt).
2. Нажмите **Connect** вверху страницы проекта и скопируйте строку **Session pooler**
   (порт `5432`). Она выглядит так:

   ```
   postgresql://postgres.abcdefgh:[YOUR-PASSWORD]@aws-0-eu-central-1.pooler.supabase.com:5432/postgres
   ```

3. Подставьте пароль вместо `[YOUR-PASSWORD]`.

Берите именно *Session pooler*. *Direct connection* работает только по IPv6, которого нет на Render,
а *Transaction pooler* (порт `6543`) несовместим с подготовленными запросами драйвера.

Менять `postgresql://` на что-то ещё не нужно: сервис сам приведёт адрес к нужному виду.

## 2. Приложение в Render

1. Зарегистрируйтесь на render.com через GitHub.
2. **New → Blueprint**, выберите репозиторий. Render прочитает [`render.yaml`](../render.yaml).
3. Заполните переменные:
   - `WT_DATABASE_URL` — строка из шага 1;
   - `WT_TELEGRAM_BOT_TOKEN`, `WT_TELEGRAM_CHAT_ID` — данные бота.
4. Нажмите **Apply**. Первая сборка идёт 3–5 минут.
5. Откройте сервис → **Environment** и скопируйте значение `WT_API_KEY` — Render сгенерировал его сам.

Сервис будет доступен по адресу вида `https://watchtower-xxxx.onrender.com`. Дашборд при первом
открытии спросит API-ключ и запомнит его в браузере. Страница `/status` открыта без ключа.

## 3. Не дать сервису уснуть

Бесплатный сервис Render останавливается через 15 минут без входящих запросов — и мониторинг
останавливается вместе с ним. Добавьте на дашборде монитор на сам сервис:

- URL: `https://watchtower-xxxx.onrender.com/health`
- интервал: `300` секунд

Запрос уходит наружу и возвращается через балансировщик Render как входящий, поэтому сервис не
засыпает. Заодно это проверка всей цепочки, включая базу.

## Ограничения бесплатного варианта

- Render прямо пишет, что бесплатные сервисы не предназначены для продакшена: возможны перезапуски
  и короткие паузы. Данные при этом не теряются — они в Supabase.
- После перезапуска сервис «просыпается» только от входящего запроса. Если он всё-таки уснул,
  откройте дашборд — и мониторинг продолжится.
- 750 бесплатных часов в месяц хватает ровно на один сервис, работающий круглосуточно.
- Supabase ставит проект на паузу после недели без обращений к базе. Работающему Watchtower это
  не грозит: планировщик обращается к базе постоянно.
- Проверки идут из одного дата-центра: сбой сети у Render выглядит как падение всех сайтов.

Для настоящей эксплуатации достаточно самого дешёвого VPS: `docker compose up -d` — и ограничений нет.
